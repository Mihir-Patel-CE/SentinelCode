# SentinelCode — Universal Multi-Language Code Review & Bug Detection Platform

SentinelCode is an enterprise-grade AI Code Review and Automated Bug Detection Platform. It integrates **deterministic static AST/scope analyzers** with **advisory multi-provider LLM reasoning** to analyze user-submitted source code across multiple languages with verifiable code evidence, actionable remediation diffs, and transparent scoring.

---

## Key Highlights

- **Universal Multi-Language Registry**: Modular analyzer adapter pipeline supporting **C**, **C++**, **Python**, **JavaScript**, **TypeScript**, and **Java** with clear extensibility for Go, Rust, and PHP.
- **Zero-Execution Static Sandbox**: User-submitted code is **never dynamically executed** in the host process. Code is parsed and inspected strictly using abstract syntax trees, compiler diagnostic pipelines, and lexical scope graphs. For C and C++, execution uses an isolated `CompilerSandbox` enforcing POSIX resource limits, secret-free environments, and `-fsyntax-only` / `--analyze` passes with zero binary execution.
- **Deterministic Static Truth + Advisory AI**: High-confidence findings are generated by deterministic rules with exact line, column, and code evidence. AI suggestions are explicitly labeled as `advisory` with `medium` confidence.
- **Evidence-Backed Remediation**: Every security vulnerability and bug pattern captures the exact snippet from user input alongside a unified diff suggestion.
- **Proportional Scoring Engine**: Security, quality, and maintainability scores reflect verified findings and input status. No false 100/100 default scores on incomplete, malformed, or failed inputs.
- **Split-Pane Developer Experience**: Dark-mode IDE layout with Monaco-grade custom line gutter, language selector with separate C and C++ options, language auto-detection, severity filtering, and review history.

## Analysis Pipeline & Status Workflow

Every user code submission proceeds through a deterministic state machine:

```
Code Editor State
       │
       ▼
Input Validation (UTF-8 size <= 250 KB, non-empty, safe string sanitization)
       │
       ▼
Language Resolution (Explicit choice or Heuristic Auto-Detection)
       │
       ▼
Modular Analyzer Registry (Dispatches to language adapter)
       │
       ├─────────────────────────────────┬─────────────────────────────────┐
       ▼                                 ▼                                 ▼
Python AST Visitor            JS/TS Structural Parser           Java Heuristic Analyzer
       │                                 │                                 │
       └─────────────────────────────────┴─────────────────────────────────┘
                                         │
                                         ▼
                            Advisory AI Provider
                     (OpenAI / Gemini / Offline Heuristics)
                                         │
                                         ▼
                         Deduplication & Normalization
                                         │
                                         ▼
                               Scoring Engine
                                         │
                                         ▼
                           Normalized API Response
```

### Analysis Status Codes:
- `completed`: Full static analysis completed successfully with zero unhandled parser exceptions.
- `completed_with_limitations`: Syntax error or unclosed delimiter detected. Analysis reported the syntax finding with line/column markers, but AST tree traversal was limited.
- `invalid_input`: Code payload failed schema validation (e.g. empty or whitespace).
- `unsupported_language`: Submitted language has no deterministic adapter; advisory AI reasoning was used.
- `failed`: Internal parser exception occurred; scores are flagged as provisional or unavailable.

```json
  "line_end": 14,

  "evidence": "cursor.execute(f\"SELECT * FROM users WHERE id = {user_id}\")",
  "confidence": "high",
  "suggested_fix": "Use parameterized queries or ORM query parameters.",
  "fix_diff": "- cursor.execute(f\"SELECT * FROM users WHERE id = {user_id}\")\n+ cursor.execute(\"SELECT * FROM users WHERE id = %s\", (user_id,))"
}
```

## Scoring Formula

Scores start at **100** and apply proportional deductions based on verified findings:

$$\text{Security Score} = \max(0, 100 - (30 \times C_{\text{crit}} + 18 \times H_{\text{high}} + 8 \times M_{\text{med}} + 3 \times L_{\text{low}}))$$

$$\text{Quality Score} = \max(0, 100 - (20 \times C_{\text{crit}} + 12 \times H_{\text{high}} + 6 \times M_{\text{med}} + 2 \times L_{\text{low}}))$$

- **Status Awareness**: If an analysis is `unsupported_language`, `failed`, or `invalid_input`, scores return `null` (`N/A`) rather than a deceptive 100/100.
- **Maintainability Index**: Computed from source line counts and finding density using logarithmic normalization.

## Quickstart Setup & Run

### 1. Prerequisites
- **Python 3.11+** or **Python 3.12**
- **Node.js 18+** and **npm**
- **LLVM / Clang Toolchain**: `clang` and `clang++` (installed by default via Xcode Command Line Tools on macOS or `build-essential` / `clang` package on Linux).

### 2. Backend Setup
```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Run database migrations
alembic upgrade head

# Start FastAPI development server
uvicorn app.main:app --reload --port 8000
```
API Documentation will be live at: `http://localhost:8000/docs`

### 3. Frontend Setup
```bash
cd frontend
npm install
npm run dev
```
SentinelCode UI will be available at: `http://localhost:5173` (or port indicated in terminal)

## Security & Isolation Guarantees

1. **No Code Execution**: User input is strictly analyzed statically without execution. For C and C++, only verification passes (`-fsyntax-only` and `--analyze`) are invoked. Compiled binaries are never executed.
2. **Compiler Sandbox Isolation**:
   - Environment variables containing production secrets, API keys, or DB credentials are systematically stripped.
   - Child processes run in isolated ephemeral directories with restricted file permissions (`0o600`).
   - POSIX resource limits (`RLIMIT_CPU`, `RLIMIT_FSIZE`, `RLIMIT_NOFILE`) prevent CPU or disk exhaustion DoS.
   - Strict timeouts (default 5.0 seconds) terminate lingering operations.
3. **Size Quotas**: Strict input boundaries prevent Denial-of-Service (DoS) and memory exhaustion.
4. **Structured Logging**: All auth credentials and API keys are automatically masked before writing to log streams.
5. **CORS & Authentication**: Pre-configured HTTP Bearer JWT tokens with guest mode support.
